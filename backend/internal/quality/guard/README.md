# 实时响应守卫

守卫验证响应是否满足配置要求的可见思考协议。通过准入并不证明完整交付、内容正确或模型能力正常；这些结果需要独立的完成事实和质量评价。

## 策略与版本

生产配置唯一存储于 `runtime_settings` 的 `quality_guard` 行。配置包含启停、模型范围、尝试上限和等待预算；`domain/guard`统一文件与管理输入的默认值、管辖匹配和范围，构造/重读非法值不会报告就绪。`guard.Service` 串行更新、先持久化，再发布不可变快照。保存使用 revision 条件更新，过期编辑或其他实例覆盖返回冲突。

网关通过实例的 `GuardSnapshotSource` 在请求开始时取得策略。范围、预算、规则版本和内核来自同一快照；热更新仅作用于后续请求。启用时缺少内核，或配置读取失败，返回 `quality_guard_unavailable`。明确关闭的配置允许旁路。后台每 5 秒从持久化权威重载，副本之间按版本最终收敛。

旧设置页面的 `requestRetry` 是只读投影；通用表单不再校验或写回该投影。守卫模型/重试参数共用独立编辑版本，通过 guard 端点保存；网络轮换另有保存与范围重置。版本响应为十进制字符串，旧安全整数输入仍可读取；管理 GET 读权威存储，持久失败可见。`DELETE /quality/guard` 以 CAS 保存真实文件默认值的新覆盖版本，保留时钟。JSON 政策由 guard 解释，通过通用 SettingsDocumentRepository 持久化，组合根无独立 SQL writer。详见 [配置扩展合同](../../../../DEVELOPMENT.md#新增设置)。

准入总预算默认为普通请求 30 秒、启用工具请求 3 分钟，覆盖选号、响应头、门控、转换和重试间开销。计时从请求开始，多个尝试共享；HTTP 传输在发布响应头前显式提交交付，提交后不再受准入计时器影响。适配器在网络请求前发布规范化后的实际工具与推理档位；网关据此调整总预算截止和两个阶段预算（Chat `web_search_options`、Messages `thinking`/`output_config` 与 `max` 等别名以规范化结果为准，客户端请求体解析只是规范化前的回退），截止仍从原始开始时间计算，已过期请求不会复活。计时器在管辖与豁免判定完成后才武装：受管辖请求的绝对截止不变，豁免请求不会在选号与候选查询阶段被提前取消。

流式准入分两个等待阶段：`createdTimeout` 从开始读取上游响应流起等待首个 SSE data 事件，默认 5 秒；首事件到达后才开始 `evidenceTimeout`，默认 3.5 秒。注释和未完成的 data 不结束首事件等待，后续元数据和空增量不重置证据预算。可见思考立即准入，明确扣留证据立即结束；已出现语义工具输出的流沿用原有判定及总准入期限。重推理请求两个阶段各使用 30 秒预算，启用工具请求的阶段预算为 24 小时，实际仍受工具总准入期限和传输空闲超时限制；工具/重推理的分类同样以规范化轮廓为准。两类超时均不构成降智证据。

配置字段与默认数值保持兼容，证据预算的起点改为首事件到达时刻。因此普通请求的完全静默尝试等待上限由先前重叠计时的 3.5 秒恢复为 5 秒；先到首事件、后无证据的尝试最多使用 5 秒加 3.5 秒，且不能延长请求总准入期限。升级无需迁移持久配置；混合版本的等待行为不同，回退会恢复重叠计时。

## 判定与交付

- 可见思考增量满足准入条件。
- 推理阶段闭合仍无思考，或正文先于思考到达，产生扣留判定。
- 密文、注释、嵌套伪字段和 usage 声明不构成可见思考证据。
- 未知协议、超限、空流、读取失败和取消使用独立错误，不作为降智证据。
- SSE 在每个事件后立即判定，后续同批数据不能覆盖已经成立的扣留结果。
- 协议版本 `visible-thinking/v2-single-choice` 将 refusal 与普通可见正文同等处理，不再将 Chat refusal 误记为空闲。可见思考要求没有 refusal 豁免。
- Chat 只支持一个 index=0（或省略 index）的选项。受守卫保护的 n>1 请求在发送前返回 400；上游多选项或非零 index 返回独立协议错误，不合并不同生成的思考证据、不投降智票。
- 被扣留的响应不得交付或提交到会话缓存。客户端协议转换失败显式报错；缓存确认在完整交付成功且必要完成事件已持久化之后。
- 救回统计在幂等交付 finalizer 中记录；首个思考后断流不会计为交付成功。

`quality_retry_scan.go` 提取协议事实，`quality_canonical.go` 与 `quality_body.go` 执行流式和整包门控，`guard.Judge` 负责纯规则判定。Build/Console 的 SSE 由 `responseflow.Stream` 统一组装，准入、Build 空闲检测、待提交会话缓存和客户端编码器借用同一事件。准入保留事件的重放不会重新组装或重复通知观察器；多行 data、BOM 与 CRLF 使用同一解释。嵌入式旧适配器保留 `quality_stream.go` 字节接口。

兼容转换管道使用 `streampipe.Transform` 统一关闭源与管道。上游关闭不等待客户端写入；正在编码的事件仍保留其计费，直到编码器退出。被拒绝的尝试、失败交付与未使用结果取消会显式丢弃缓存缓冲；完整读取后还必须取得交付与完成事件确认才允许提交。

## 资源与验证边界

`attemptResources` 统一拥有每个物理请求的取消函数与响应体。生产与探针共同通过 `runPhysicalAttempt` 调用适配器并接管响应体；`deliverySession` 拥有生产响应的交付、完成记账、缓存确认和用量审计。错误同时带响应时也会关闭；同号刷新会先结束旧请求；所有关闭和账号释放都幂等。结果交付前过期或请求取消时，立即释放响应和并发槽位。

Build 搜索过滤、工具兼容处理与 Build/Console 对话转换均在原始响应准入之后运行。非流式成功响应不再由适配器提前读完整包。JSON 检查与转换借用同一份输入；借用期间即使响应被关闭，计费也保持到借用结束。

流式前缀上限 4 MiB，非流式输入上限 32 MiB，完整 SSE 事件上限 8 MiB。`responsebuffer` 在分配前预留容量，扩容同时计入新旧数组；覆盖守卫前缀、读取泵、JSON 输入输出、SSE 事件与多行数据组装、事件元数据及待提交缓存。解析前另按 JSON 字节与结构节点预留保守工作区；转换器跨事件状态上限 16 MiB，推理 ID 最多 4096 个，客户端传输检查也在同一请求预算中。

单请求默认 96 MiB、进程默认 512 MiB，超出返回独立的 `response_resource_exhausted`，不投降智票、不轮换账号。工作区与状态采用保守容量估计，可能在输入字节上限之前拒绝复杂响应；这些数值不是进程 RSS 上限，Go 堆、连接、请求输入和缓存存储仍有各自开销。关闭转换管道会中断源和写端，并等待转换器释放状态后返回。

解析回归使用结构化数据、转义与 Unicode、重复字段、深层嵌套和不同分片方式。字段扫描的完整性以 `encoding/json` 差分验证。测试仅使用构造响应、本机 HTTP 服务与最小化 fuzz 样本。

```sh
go test ./...
go test -race ./internal/application/gateway ./internal/quality/guard ./internal/app ./internal/application/settings
go test ./internal/pkg/jsonpeek -run '^$' -fuzz '^FuzzValidatedObjectFields$' -fuzztime=20s -parallel=4
go test ./internal/application/gateway -run '^$' -fuzz '^FuzzGuardDecisionPartitions$' -fuzztime=15s -parallel=4
```

本地测试不提供生产误判率、真实流量峰值内存或跨副本严格一致性的证明。运行记录、实际账号和出口信息保留在本地，不随源码提交。

验证方法与变更范围见[开发指南](../../../../DEVELOPMENT.md#验证入口)。合成回归和 fuzz 用例随源码维护；执行输出、性能样本和原始上游轨迹留在仓库外。

## 物理尝试身份

`attemptmeta.Identity` 随响应保存网关请求 ID、物理尝试 ID、账号、模型、规则版本、策略 revision 和出站时的出口版本。实际 HTTP 调用在出口租约边界固定身份；客户端转换与辅助请求不能改写此前响应的身份。证据入库保存完整身份，重载保留原始时间与版本，上报时不再查询当前 epoch。

路径注册和实际验证分开表示。旋转代理只有登记版本时仍标记为 unknown；普通流量的登记信息不冒充实际出口验证。准入通过和最终完成采用不同的事件类型，完成事件不会重复增加准入样本。普通流量的准入通过与完成只留事件台账,不进入健康对照样本；归因窗口排除历史版本误写的 traffic/delivered 观测,保留原始行用于诊断。

`exchange` 事件单独记录每次实际 HTTP 提交，包括连接失败、业务面回退、恢复和压缩请求。每个请求最多预留 128 个实际调用记录，容量在提交传输前取得；达到上限返回 `physical_attempt_limit`。记录包含响应头结果、状态、读取字节数、EOF/提前关闭/读取失败与用量，不保存响应正文或认证头。用量区分未报告和明确的零值；原始协议用量优先于转换后的回填。已缓冲并关闭的交付响应在 finalizer 取得用量后才固定记录。批次事务失败全部回滚，已确认事实不再修改。

## 持久事件与限制归属

每个物理尝试分别产生准入与完成事实。准入通过仅表示规则满足；中断、取消和最终完成各自留档，不重复增加准入样本。`q_guard_event` 保存原始身份和事实，`q_guard_outbox` 保存处理租约与重试时间。请求只有取得事务回执后才能继续；失败返回 `quality_event_unavailable` 并留下短期本地保护，不能伪装成已可靠接收。

拒绝尝试先关闭响应、归还账号并发租约，再以短事务原子写入事件、owner 临时限制和待处理任务。只有降智准入事件需要后台处理；exchange、正常准入、完成和恢复事实入库时即标为归档完成，不再占用调查队列。后台工作进程进行幂等证据写入与立案；单次处理预算 5 秒，租约 15 秒，失联后可重新认领。旧工作进程不能确认新租约。

完成跟踪只在内存锁内操作事务写入标记，不持锁查库；并发完成先返回时标记阻止迟到的准入记账重新续租。正常准入在同一事务创建 `q_guard_completion`，留下由当前进程持有的完成义务，并取得独立的在飞容量。完成事务写入最终事实、删除义务并释放容量，不需要重新争抢调查队列名额。短暂写入失败由有界本地重试保留原始事件；重启或长期存储故障后，持久义务仍可恢复。每 15 秒续租/恢复，义务租约为 2 分钟；失去续租时记录 `recovery/unconfirmed`，不推断交付成功或失败。之后到达的真实 completion 仍能独立入库，原恢复事实保留。没有完成事实的准入记录不能被当成完整交付。

临时限制以事件 ID 为 owner，默认 2 分钟；案件拥有自己的当事方限制。释放一个事件不会释放其他事件或案件。选号缓存用于候选筛选，取得并发槽后再读数据库检查有效限制；该读之后提交的限制作用于后续准入。人工启停、429 和其他健康字段保持各自含义。

迁移仅识别历史 missing-thinking 标记，将其转为最长 2 分钟的临时限制。旧禁用状态无法可靠区分人工操作，因此保留 `Enabled`，并保存 `legacy_disabled_review` 迁移记录供人工核查。迁移幂等，不延长既有期限。

已处理事件保留 7 天，后台每分钟进行最多 5 秒的清理。每个事务最多处理 1,000 条事件，连续提交直到追平或用完时间预算；尚未处理或仍有完成义务的事实不清理。故障测试覆盖事务回滚、工作进程失联接管、重复计票、限制归属、旧数据迁移、跨实例准入复查和释放容量后再落库。

调查队列与在飞完成义务分别受默认 10,000 个名额约束，事务同时取得相应容量、写入事实和创建任务。重复事实不占新名额；只有相应处理确认或完成义务解除才释放名额。已知积压满载或存储不可读时在下一次上游调用前拒绝，容量竞争仍由写入事务最终裁定。升级按已有未处理任务初始化计数；旧版已经交付的请求无法补造完整的完成义务。

本地临时保护最多保留 8192 个 owner。达到上限时保留已有 owner，并在新事件的有限期限内启用全局保护，不驱逐正在生效的限制。`/guard-stats` 提供进程响应缓冲容量/峰值/拒绝数、本地 owner 数/溢出期限，以及持久队列的待处理数、最老事实时间、租约数和重试数。它还提供 `inFlight`、尚无真实完成事实的 `unconfirmed` 和清理积压的 `oldestExpiredAt`；存储查询失败显式返回 `backlogUnavailable`。

## 重放与取证完成

重放政策来自请求工具能力，并在实际请求规范化后再次检查。未交付的客户端函数调用、自定义调用和已知只读搜索可以重试；未知服务端工具的副作用无法确认时只允许一次生成。该限制同时传递给 Build 平面回退、推理密文恢复与压缩重试；发送 Idempotency-Key 不等于已经证明跨账号工具执行幂等。

后台探针始终禁用内部重放，不提交用户会话输出。v2 使用简短普通请求、`low` 推理档位和 128 token 输出上限；首个有效思考增量就是本次测量的正常证据，立即取消并关闭、回收物理流，不等待正文或成功终态，也不检查答案。已有的物理观测照常持久化，不伪造完整生成或完整 usage。明确降智同样立即停止；证据形成前的超时、失败终态、读取中断或资源超限为 error。整体测量最长 90 秒。旧 v1 探针继续要求成功的 response.completed 和正常结束，其完成阶段上限为 15 秒、1 MiB。

探针与生产请求从同一权威取得策略快照,实际调用身份贯穿主测量、对照测量、任务持久化和证据观测。取证结果不能用任务计划中的账号或当前出口代际覆盖实际身份。裁决读回时再次核验账号、出口代际、策略版本与模型；缺少物理身份的历史任务仅保留诊断,不同策略下的测量不合并归因。旋转出口和未验证路径不能被当作固定出口。探针准入与完成检查借用同一 SSE 事件,完成消费的剩余字节预算在下一事件组装前生效。

案件冻结触发事件 ID、基线身份和 `thinking-presence-v2` 实验规格，初始任务与替代任务继承同一规格。固定样本为简短问候请求；生产请求的工具、推理档位和客户端协议只作触发来源。测量与对照统一使用无工具、`low` 推理档位的 Build Responses 请求，必须匹配原 provider、模型、策略 revision、规则版本及样本。模型路由消失、规格不支持或配置变化时返回不可采结果。旧 v1 案件继续遵守其冻结的原始轮廓，不自动升级或重开。它测试可见思考协议，不重放用户正文，也不证明原问题的答案质量。旧裁决协议不会自动获得新实验的可信度。

探针使用生产账号的同一并发计数和相同进程响应缓冲预算。其账号槽、身份槽和全局测量槽使用 2 分钟租约，覆盖最长 90 秒测量和结束清理；进程失联后可在任务租约之前恢复容量。短租约只延长共享 Redis 键的有效期，不缩短活跃生产请求的租约。额外限制同时进行的测量最多 2 个，同一账号或已知身份组最多 1 个，限制由已配置的运行态存储共享；多实例配置要求 PostgreSQL 和 Redis。取证资格豁免仅绕过质量限制，不绕过账号容量、认证或配额条件。

## 调查任务与多实例状态

8 个工作槽各自认领下一项任务，每项任务独立使用 2 分钟执行上下文；慢任务不会阻塞空闲工作槽。任务保存进程所有者和 3 分钟租约，每 30 秒续租。写回必须同时匹配 running、所有者和未过期租约。启动只回收过期或旧版无所有者的任务，不取消活跃副本的工作。回收、裁决评估和统计记录恢复独立运行。

done 任务与 `q_probe_projection` 的恢复载荷在同一事务提交。投影采用稳定的 Observation.EventID 去重，写入后确认丢失可以重试；任务或案件已被删除也不丢失待恢复载荷。恢复循环不依赖新探针。升级按批检查旧 done 行，匹配已存在的旧观测后只补建缺失记录，不再次发送上游请求。

登记处状态写入通过数据库状态行串行化，在事务中校验 revision 后按需加载当前状态，提交后才发布本地快照。当前代际使用 `q_node_epoch` 指针，与历史追加原子更新；热刷新不加载历史档案，未变化 revision 跳过重载。探针入队只持有关联案件的锁并取得冻结规格。court 的跨实例协调租约为 1 分钟，工作上下文最多 45 秒，受协调的写入在事务中再次检查所有者。评估先处理过期案件，每案最多 1 秒；未到期案件最多 5 秒，且两个方向与匹配控制在同一补测轮次复用候选查询。每案都保留其他案件的预算，跨实例持久游标记录上次尝试，慢案件不阻止队列轮转。账号和出口在最终租约边界直接查库判断资格；候选快照和证据窗口每 3 秒刷新，用于选择与显示，不作为最终准入依据。这一设计不承诺把已发生的数据库读取与随后网络调用合成一个分布式事务。

失败分类由实际故障操作写入来源/阶段/原因，贯穿网关与任务持久化。内部容量、取消、完成预算、配置、持久化和未知故障不可作为定罪依据；历史自由文本类别也不可采。明确的上游失败仍须满足当前协议的身份、独立路径和匹配控制条件。

升级新增完成义务、任务投影、协调、当前代际和状态版本表，并给任务添加实验/租约字段。旧运行中任务无法证明所有者时取消，旧完成任务只恢复观测。升级时应先排空旧工作进程，避免新旧协议混跑；缺失的历史物理身份和完成事实不会被补造。
